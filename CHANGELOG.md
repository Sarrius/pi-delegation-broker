# Changelog

All notable changes are documented here. This project follows [Semantic Versioning](https://semver.org/) after `1.0.0`.

## Unreleased

- **Anthropic subscription OAuth is now supported by the controller proxy.** The controller accepts an exact current OAuth access token, sends Claude Code's Bearer/identity headers, never forwards a refresh token, and the owner can point the live canary at the existing provider entry in `auth.json`.
- **External supervisor requirements are now explicit.** The package documents the launchd/systemd boundary, attestation-failure recovery and restart/reconciliation obligations; tmux/caffeinate are not represented as crash supervision.
- **Workflow mutation is now bound to the owner session.** New task/workflow jobs persist the parent session identity; append, close and cancellation operations fail closed from another session, and workflow join acceptance requires a controller verification callback rather than trusting child semantic status.
- **Integration now requires controller verification authority evidence.** Accepted-proposal semantic flags cannot authorize a worktree merge; proposal and final integration receipts are bound to the patch digest and expected head before any target mutation.
- **Protected repair approvals are signed and expiry-bound.** Repair proposals persist the approved receipt and revalidate it against the immutable proposal before controller verification, fresh-process canary, reconciliation and resume. The parent extension now exposes controller-owned repair propose/approve/run/status tools; without an owner-injected repair adapter, run remains fail-closed.
- **The Pi extension now supports owner-injected credentialless proxy startup.** Supplying `ctx.controllerProvider = { providerTransport, routeResolver }` makes the attested `controller-provider-proxy.ts` the child provider and omits scoped child auth; the direct `writeScopedChildAuth` branch remains compatibility-only and explicitly non-live-ready. A skipped-by-default live Anthropic child canary exercises this boundary without putting the key in child state.
- **Cumulative controller budgets now stop overspend across retries and workflow nodes.** Lease-side input reservations use a conservative UTF-8 upper bound before a real proxy send; output usage is accounted transactionally across repeated streams; logical runner failover sums input/output usage and adopts the controller attempt cap; workflow physical attempts are gated by the root, root output limits are passed down, and output-budgeted teams serialize by policy.
- **Acceptance execution is now controller-owned.** Delegation and workflow callers can choose only fixed checks (`git-diff-check`, `npm-check`, `npm-test`, `npm-release-check`, or bounded symlink-safe `file-equals`); caller-supplied `argv`, claims and executors are rejected. Checks run with `shell: false`, a sanitized offline environment and bounded output, including proposed-patch verification in the controller scratch worktree.
- **Provider availability is now time-aware.** The controller rechecks OAuth expiry periodically (including Unix-second and millisecond formats), supports OAuth access tokens in controller-side model probes, applies provider additions/withdrawals incrementally while leases are active, represents an empty authorized fleet instead of retaining expired accounts, and updates broker health from probe failures/recovery. Model-list throttles use bounded half-open unknown probes rather than incorrectly opening the long inference quota breaker; actual inference 429s retain the stronger account cooldown. `Retry-After` is parsed and retained only as a bounded delay.
- Separate the child contract into independent axes: `thinking` (`auto`, `inherit` from the live parent session, or an explicit level that is never silently lowered), `route` (`auto`, `inherit_model` for the parent's exact current model, and `peer` which fails closed while no calibrated quality-equivalence exists), and an optional schema-versioned `role`. Roles are framing only — quoted inside delimiters, placed before lease rules so the lease speaks last, sanitized against prompt-structure forgery, and unable to grant any tool or authority. Recovered workflow node contracts are re-validated; invalid axes fail closed instead of coercing to defaults. Explicit reviewed `skills` are hashed, capped and passed as `--skill` while `--no-skills` keeps ambient discovery off; a skill cannot grant a tool or effect capability, and a mutated file fails closed against its attested digest. Requested and effective effort are both persisted; the fleet shows `requested→effective` when a provider changed it. Available per task and per workflow node, so one stage can run at peer level while its siblings stay cheap. `inherit_model` is implemented as a selector filter (`requireModelIdentity`) applied beside every existing gate rather than as an override: a named model that is legacy, wrongly provenanced, unhealthy or below the tier's quality floor is still refused, and an unavailable identity denies instead of quietly routing elsewhere.
- Add a bounded live terminal fleet: footer summary, width-aware below-editor active task/node rows and `/delegation-broker fleet [active|all|id <job>|<job>]` detail show actual safe account/provider/model, requested/effective thinking, retry attempt, elapsed/progress age, token/cache usage and durable-versus-volatile state without prompts, child prose, terminal controls or credentials. Runner events drive positive progress; silence is unknown; recovered attempts render lost/reconciling; terminal reports retain safe route/effort/usage projections.
- Make cancellation reach work that owns no child process yet: `abort(id)` now matches the logical run and its failover attempts, aborts a pending admission and stops a run parked in a capacity wait, and `dispose()` aborts admissions, clears volatile attempts and refuses later launches.
- Close durability races exposed by the fleet: terminal reports reconcile nonterminal task/node projections (including pre-upgrade node reports without `logicalId`) before restart can replay them, cancellation or deadline expiry that races a completed child preserves the paid-for artifact instead of discarding it, durable workflow cancellation cannot be overwritten by stale scheduler state, and a create-once sent marker prevents stale report JSON from resurrecting wake delivery.
- Add Slice 3 recovery primitives: the controller records structured immutable defect observations from tool/controller boundaries; children can publish bounded partial checkpoints through lease-scoped IPC; only controller schema/provenance-accepted checkpoints are persisted into a replacement prompt, conflicting partials are withheld, and original artifacts remain immutable.
- Bind durable delegation roots to the parent Pi session and compaction cursor. Before each agent start the extension injects only bounded controller state (root ids/statuses/node counts), never child prose; session restart and `session_compact` re-establish the binding instead of treating an in-memory parent context as the recovery source.

- **Background delegation now wakes the parent automatically.** A terminal top-level task/workflow queues a typed hidden custom `followUp` with `triggerTurn: true`, so an idle parent collects the durable report and continues instead of waiting for another owner message. It never calls `sendUserMessage`; because Pi maps custom messages to provider-visible user role, the always-on `delegate_collect` prompt guideline provides persistent controller-state system framing and the payload carries only bounded IDs/statuses, never child text. Persistent create-once pre-send claim, sent and read markers prevent ambiguous crash replay, duplicate model spend and collection/delivery resurrection. Claim paths are never automatically released, stale-reaped or pruned; terminal bursts coalesce, definite unclaimed pending wakes recover after restart, legacy unread reports do not replay, and system-prompt inbox notice remains the failure/ambiguity fallback.

- **Read-only children no longer spend a model turn declaring every observation.** The child guard now declares and authorizes the closed `read`/`grep`/`ls`/`find`/`test` set automatically, while effect tools still require the model's exact prior `broker_declare_action`. This removes repeated declaration/read protocol loops that exhausted Cursor child turns and produced `incomplete` failovers. Fresh live observe and effect canaries both pass.

- **Live delegation recovers and drains.** Unknown routes get bounded probes, busy accounts queue without spending attempts, incomplete tool turns are not success, and settled parents reap orphan RPC children. Live canaries: `LIVE2_OK`, `UNKNOWN_LIVE_OK`, `CAPACITY_PROTOCOL_OK`.

- **`/delegation-broker stop` is a real deactivation now.** The command used to only set a flag: the broker process kept running, held the lock and socket, and auto-started again on the next session regardless. `stop` now shuts the supervisor down (lock and socket released), and a stopped broker no longer auto-starts on `session_start`. `start` activates it again.

- **A declaration written as a JSON string no longer blocks the invocation.** Cursor's `claude-4.6-opus-*` children declared `read` with args as a JSON-encoded string, then invoked it with the object form. The behavioral monitor hashed both literally, called the invocation "differs from declared action", blocked every tool, and all four Cursor routes settled with empty text. `requireAction` now parses a stringified-JSON args payload before hashing; a string that is not JSON stays verbatim.

- **A heartbeat no longer leaves the child unauthorized.** `heartbeat` used to extend only `leases.expires_at`. The IPC token copies expiry at issue time, and `leaseForCapability` requires **both** rows to be live. Live canary `workflow-mt166q44-1-pkg-name` heartbeated the Cursor lease and still got `unauthorized` 655ms after the original 30s snapshot, then settled with empty text which the runner treated as `completed`. Heartbeat now updates `lease_capabilities.expires_at` too. An observe child that settles with no answer is `unavailable` and fails over. `mcp_pi_read` declared for allowed `read` is the same tool.

- **A teammate no longer dies because the first child took the only Cursor slot.** Each account admits one work child (`maxConcurrent` 2 minus a control reserve). Two parallel `delegate_workflow` nodes both selected Cursor, the second got `denied_capacity`, and the resolver treated that as "no compatible broker capacity" — even though Kimi and Codex were idle. A full allow-list now excludes those resources and selects again. Separately, the workflow scheduler was dropping `tier` and `capabilities`, so every node looked like a cheap read and collapsed onto that one slot.

- **Cursor (and other proxy-backed OAuth) no longer crash the parent Pi session.** Isolated children run `--no-extensions`, so Pi cannot use a copied Cursor `type: oauth` entry and threw `No API key found for cursor`. That RPC error was an unhandledRejection that Node promoted to `uncaughtException`, which exited the interactive session. `writeScopedChildAuth` now materializes a proxy-backed OAuth access token as `type: api_key` (the local Cursor proxy reads Authorization and uses that token as the leased account). Native Anthropic/Codex OAuth is still copied verbatim. Child RPC request promises keep a rejection sink so a late error cannot kill the parent, and `No API key found` classifies as `auth_fatal` so failover continues if it still happens.

- **The watcher now reads the real model list from `models.json` for auth-only providers.** A provider present in `auth.json` with endpoint config but no `models-store.json` entry — exactly what pi-multi-account provisions for its Cursor and Kimi rotation slots — used to register a single placeholder model named `default`, hiding every real model from routing. When `models.json` carries a model list, those models (string or object form) are registered instead; the placeholder remains only when no list exists.

- **Unread background reports no longer steal the parent turn.** `before_agent_start` used to inject the inbox as a `custom` message (`display: false`). Pi converts custom → user and appends it after the actual prompt, so the last user message — the one the model treats as the current task — became "read these reports". That collided with pi-multi-account: failover continuation is itself a `sendUserMessage` follow-up, and a process restart re-blasted unread files that are never pruned (including failed probes from the previous day). The notice now goes through `systemPrompt`, existing unread ids are seeded at session start, and a failover continuation turn is skipped so the continuation prompt stays the task.
- **Breaking:** `catalogToBrokerRegistry` now maps a catalog by what actually constrains delegation. A resource is one `(provider, model)` pair rather than one provider represented by its strongest model, so a provider's cheap models are selectable instead of invisible; a capacity group is the account, because every model of one account draws on one quota, so a rate limit cools all of them; and a profile is a capability tier shared across providers (`caps/<sorted.capabilities>/v1`) rather than a per-provider model identity, which is what allows a contract pinned to a class to be served by whichever provider is currently alive. `maxConcurrentPerProvider` now defaults to 2, since a single-slot group reserves its only slot for control admission and can never admit work. Model ids may carry vendor paths, `:variant` suffixes and `~rolling` aliases, and a provider may publish up to 4096 models — a real aggregator account publishes ~350, and the previous 256 cap made `DynamicProviderWatcher.refresh()` throw while `start()` discarded the error, so the dynamic registry silently never loaded.
- Added `model-selector.mjs`: controller-owned capability-aware selection. `selectModelForTask` derives a task's required capabilities, picks the weakest sufficient capability tier that has a usable resource right now, and returns a contract the broker accepts plus the ranked alternatives. Two asymmetric rules govern it: downward substitution is forbidden even when a weaker class is all that remains, and upward substitution is required when the cheapest sufficient tier has nothing alive, so delegated work finishes instead of being denied for the sake of a saving. Resources rank by inventory confidence before cost, and `allowedProviders` / `excludeResources` confine which accounts delegation may spend. `createSelectContract` builds the launch resolver's callback from a registry read per launch, so a long-lived resolver does not route against a provider set captured at construction.
- Added `SqliteLeaseBroker#updateRegistry`: an incremental registry update that applies while work is in flight. `reloadRegistry` replaces the whole registry and therefore refuses whenever any lease or task is active — under continuous delegation that moment never arrives and a newly authenticated account would never become usable. Additions now apply immediately; a withdrawn resource that still carries a live lease is retired (takes no new work, deleted once its last lease ends) instead of being deleted underneath it; a withdrawn resource that reappears mid-drain is restored; and a policy change to a live capacity group is reported as deferred rather than silently applied over existing admission accounting. Added `SqliteLeaseBroker#inventory` so a controller can see live health, retirement, cooldown and breaker state — a registry snapshot describes the shape of the world, not which parts of it are answering.
- `BrokeredChildRunner` now finishes a delegated task across a changing provider set. `model` is optional: without it the controller's selector chooses, and the child launches on the model its lease is actually accounted against (`resolvedModel`) rather than the one merely predicted, since a contract pins a class and the broker may lease a different resource in it. `run()` classifies a terminal child failure as `rate_limited`, `auth_fatal`, `unavailable`, `context_exhausted` or `fatal`, reports provider health to the broker, excludes that resource and retries elsewhere within a bounded attempt count; a context overflow re-routes to a larger-context class without marking the healthy provider down, and a genuine task failure is not retried. `BrokeredLaunchResolver` gained `reportProviderRateLimited` / `reportProviderUnavailable` — a throttled account still appears connected in Pi's own files, so a failed attempt is the only way staleness can be observed at all — and an injectable `spawnChild` seam so the failover path is testable without a real Pi process.
- `DynamicProviderWatcher.refresh()` now reports `failed` with a reason instead of throwing into a discarded promise, fingerprints model ids as well as provider names (a provider gaining or losing a model previously reported `unchanged` and never reloaded), and does not commit a fingerprint for a catalog it could not represent or a registry update that was deferred.

- Added `ControllerAcceptanceVerifier`: a fixed controller-owned, serial command/test verifier plan with injected read-only runner, per-check timeout/abort, retained controller evidence and standard acceptance validation. It exposes no worker-selected command, expected output or evidence descriptor; malformed, failed, timed-out, runner-error and overlapping verification attempts reject. `ControllerVerificationAuthority` now retains a receipt bound to the exact task/lease/fence, and `finalizeVerifiedTask` rejects an otherwise well-formed unattested/replayed receipt. `ControllerQueuedTaskVerifier` provides the controller-only queued child-close → fixed verification → terminal-finalization lifecycle.
- Added a durable controller-owned effective-capability binding for each lease. `BrokeredLaunchResolver` binds the compiled capability before passing a lease-scoped token; children can retrieve only that record, while controller IPC centrally performs behavioral action declaration, blocking authorization and completed-result observation with controller-derived state digests. Behavioral audit events are separate from provider telemetry/health. Added a source-auditable Pi `tool_call`/`tool_result` reference extension that requires a one-action declaration and lease heartbeats.
- Added controller-pinned launcher attestation for the source-only `pi-subagent-workflow` seam: each explicit extension has a reviewed SHA-256, the behavioral extension must be final, bytes are rehashed before spawn, and `broker_declare_action` must appear in the child startup report before handoff. `BrokeredLaunchResolver` rejects an effect-capable child before reservation if its pinned attestation configuration is absent. The seam remains unaccepted; effects stay unavailable until upstream/reviewer acceptance and final-gate verification.
- Added `captureProviderContext`: one shared closed, lossless child→controller context vocabulary for fake and real transports. It allows only text system/user/assistant messages and named JSON-schema tools; provider options, response IDs, replay/cache state, unknown modalities and unknown fields fail before route or credential resolution.
- Added a low-level `AnthropicMessagesTransport` as the first real-provider transport primitive and wired it through the same controller IPC frame/settlement boundary as the fake transport. `ControllerCredentialStore`, owner-only credential-free `ControllerRouteTable`, and expiring/bounded `ControllerLiveProviderApproval` construct its one exact controller route; it has no environment/keychain/OAuth fallback, account rotation, retry, redirect or automatic failover. IPC accepts the real transport only with its paired route resolver, never alongside fake transport. It is mock-tested only and has made no live provider call.
- Integrated the capability compiler into the launch resolver: `BrokeredLaunchResolver` now creates an `EffectiveChildCapability` from the contract and lease, compiles it into `promptRules` (child-visible) and `authorizationPolicy` (controller-enforced), and includes both in the returned policy. A `deriveAllowedTools` helper maps operation classes to default tool sets.
- Added unified capability compiler: `createEffectiveChildCapability` validates and deep-freezes one immutable child-facing capability (operation class, allowed tools, doneWhen, budget, behavioral enforcement); `compileEffectiveChildCapability` generates prompt-visible rules and executable authorization from that single source. `BehavioralRunMonitor` now optionally accepts an authorization policy that denies tools outside the allowed set (terminal `tool_not_allowed`) and effect-capable operations without a wired blocking monitor (terminal `behavioral_enforcement_unavailable`).
- Added `RoutingBoard`: dynamic, continuously updated scoreboard tracking machine-verifiable outcomes per (resource, capability) pair. Uses Wilson score confidence intervals for routing scores (small samples don't outrank large), exploration bonuses for under-observed resources, drift detection via rolling-window divergence, consecutive-failure exclusion, recency decay, and export/import for persistence. The one-provider degenerate case reduces to monitoring. `ControllerVerifiedRoutingBoard` now records only receipt-bound controller verifier outcomes after broker terminal finalization and can reorder only the exact signed resource candidate permutation; model-graded, child, and provider self-reports are rejected.
- Added `provider-catalog.mjs`: converts a Pi modelRegistry snapshot (populated by pi-multi-account or other extensions) into a broker registry. Each provider becomes a resource in its own capacity group; each provider's strongest model becomes a profile with derived capability supports. The broker consumes a plain catalog snapshot — it does not know about multi-account as a package.
- Added transactional registry reload: `reloadRegistry` validates the candidate, denies reload while active leases or pending tasks exist, atomically deletes and re-inserts the registry in a single transaction with SQLite rollback on failure.
- Added `ArtifactPipeline` with bounded pending queue, byte cap, ordered drain, terminal durability barrier, and re-attemptable failure. The streaming path calls `pipeline.barrier()` before `settlement.markPersisted()`; if the barrier fails, the crash-repair class stays `terminal_unpersisted` instead of treating the attempt as durably settled.
- Wired framed streaming into the IPC layer: children can now send bounded typed context (systemPrompt, messages, tools, options) via the new `providerStream` method, which validates context through `captureLosslessJson`, creates an immutable `AttemptRouteSnapshot`, streams frames back through `ProviderStreamAssembler`-validated grammar, and settles through `AttemptSettlement`. The legacy digest-only `providerAttempt` remains for backward compatibility. A `streamProviderIpc` client reads NDJSON frames until the validated terminal. Real transport wiring requires the separately described exact-route, mock-tested transport path; credentials are never included.
- Implemented deterministic provider proxy protocol machinery: immutable `AttemptRouteSnapshot` with one-time route/credential fingerprinting, versioned framed envelope validation, strict stream grammar (block lifecycle, tool-call identity pinning, cumulative usage monotonicity), exactly-once terminal CAS, attempt phase machine with crash-repair classification, and closed terminal/outcome vocabulary with provenance and retry-eligibility properties. No transport, credential, or IPC wiring is included; live use remains prohibited.
- Added the versioned controller-owned real-provider proxy design gate, including strict stream grammar, immutable route/account binding, terminal/outcome taxonomy, cancellation, backpressure and adversarial acceptance tests; implementation remains absent and live use remains prohibited.
- Behavioral action/result hashing now uses one bounded detached lossless-JSON snapshot; lossy numbers, sparse/decorated arrays, cycles, accessors and exotic containers fail closed instead of colliding or changing after declaration.
- Added exact ready-task claim, pre-handoff requeue and `awaiting_result` reconciliation; later controller verifier receipt finalization supersedes terminal parent-result completion.
- Added clamped queue aging, protected control/verifier dispatch-window representatives and per-class p95/max wait metrics so neither strict priority nor an aged backlog hides a class.
- Effect-capable contracts now fail closed with `behavioral_enforcement_unavailable` until a trusted launch path asserts a wired blocking monitor; the enforcement capability is carried on admitted leases.
- Added command/file/test/URL semantic recapture projections and validator integration instead of byte-exact spot audit; volatile normalization is opt-in and conflicts fail closed when acceptance names the stripped field.
- Backward clock steps now fail closed against the durable ledger time floor rather than extending capabilities.
- Added contract `doneWhen`, prompt-digest binding and positive latency-budget admission checks.
- Added deterministic behavioral monitoring for no-progress, typed action mismatch, declared-change reconciliation and completion claims.
- Replaced digest-only evidence indexing with redacted content-addressed retention, restart verification, corruption detection and explicit pruning.
- Added durable task waiting with explicit recovery owner/deadline and supervisor dispatch.
- Added `control | verify | work` admission reserves to prevent work fan-out from starving merger/verifier capacity.
- Added confidence-labelled schema-v2 inventory enforcement, registry-defined cooldowns and a one-probe half-open breaker.
- Registry/persisted-policy mismatches now fail closed instead of silently retaining stale capacity or admission rules.
- Added controller-rooted evidence validation; self-reported evidence cannot satisfy acceptance.
- Queue size is hard-bounded; high-risk contracts must declare all three hard budget dimensions and positive caps.
- A success from an older in-flight lease cannot close a breaker opened by a concurrent 429.
- Expanded deterministic liveness, priority, cooldown and evidence tests.

## 0.1.0-alpha.1 - 2026-08-15

OIDC provenance validation release. No runtime changes from `0.1.0-alpha.0`.

- Published through the verified GitHub Actions trusted publisher with provenance.

## 0.1.0-alpha.0 - 2026-08-15

Initial public research release.

- Single-host SQLite lease broker with fencing, TTL, shared capacity and redacted ledger.
- Owner-only Unix-socket IPC with controller and child-scoped authority.
- Signed Ed25519 registry verification and supervisor lifecycle reference.
- Controller-only brokered launch resolver and deterministic fake transport.
- No real provider proxy, credential storage, account discovery or multi-host coordination.
